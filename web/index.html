OPERATING OUTCOMES

The expensive part isn't typing commands. It's knowing what's happening and what's safe.

Reticle is designed to reduce operational ambiguity: less time reconstructing the system, less uncertainty about the next move, and more context that survives the incident.

TIME TO UNDERSTAND

Orient around one live model.

See what exists, what is unhealthy, what depends on it, and how fresh the evidence is. This helps reduce incident ambiguity before the team starts changing things.

TIME TO SAFE NEXT ACTION

Shorten the path from signal to response.

Put current evidence beside preconfigured actions with approval, timeouts, and optional preconditions instead of improvising an unreviewed command during the incident.

HANDOFF AND CHANGE CONTEXT

Preserve operational context.

Keep topology, current evidence, ownership notes, and action context together to reduce change-context latency and operational handoff time across shifts and incidents.

MAP AND OPERATE

Evidence first. Guarded action second.

Start with fixed HTTP and read-only SSH probes. When those cannot express a specific diagnostic, Desktop's one global privileged toggle can enable reviewed remote SSH commands, or local Bash on Unix hosts, as persisted checks or guarded named actions. UI-created checks default to enabled and viewer-visible, with no per-check acknowledgment; execution remains behind the global Desktop toggle or Team's daemon flag and editor gate, plus bounded output, timeouts, and least-privilege identities.

Desktop may also open a separately warned live shell for its local operator. Team has no browser or ad-hoc shell. Team viewers see bounded check results on the shared canvas but never command text or execution controls; JSON, MCP, and chat remain read-only.
